# 三分钟复试项目陈述

先在自己电脑上完整跑一遍项目并读懂核心代码，再按真实参与情况修改“我实现了”等措辞。不要把自己无法解释的部分说成独立完成。

## 0:00–0:25：问题

老师好，我展示的项目叫 ArcGIS Pro Guardian。它解决的是 ArcGIS Pro 工程交付前的质量检查问题。一个 `.aprx` 在作者电脑上能打开，并不代表换一台电脑后数据源仍然有效，也不代表坐标系、地图结构和布局满足交付要求。传统做法主要依靠人工逐项检查，结果不稳定，也很难放进自动化流程。

## 0:25–0:55：目标

我的目标不是再做一个地理处理算法，而是把工程级风险转换成可重复执行的发布门禁。工具以只读方式打开保存过的 `.aprx`，检查地图、图层、独立表、布局、地图框、数据源路径和空间参考，再输出稳定的问题编号、健康分和处理建议。

## 0:55–1:35：设计

项目分为三层。第一层是 ArcPy 审计核心，负责采集项目结构和生成 finding；第二层是策略与基线层，团队可以调整每种检查的严重级别，也可以把本次结果和历史 JSON 基线比较；第三层是交付层，同一套引擎既可以通过命令行运行，也可以作为 ArcGIS Pro Python Toolbox 使用，并输出 text、JSON、Markdown 或独立 HTML 报告。

我刻意把核心逻辑做成不在导入阶段依赖 ArcPy，这样评分、策略、差异比较和报告渲染可以在 GitHub Actions 中使用模拟对象做单元测试，而真实 `.aprx` 审计则在 ArcGIS Pro 自带 Python 中验证。

## 1:35–2:15：案例

案例的 Before 工程包含一个空地图，没有布局。Guardian 给出 `EMPTY_MAP` 和 `NO_LAYOUTS` 两条警告，健康分是 88，状态为 review。改进时我增加了 WGS 84 样例数据和 A3 布局，并清理了布局模板自带、但在当前环境中空间参考不明确的底图。

After 工程包含两个地图、两个图层和一个布局，健康分达到 100，状态变为 pass。基线差异显示分数提升 12，解决两项警告。报告仍保留两条本地绝对路径信息，并通过公开策略说明为什么它们在演示环境中不阻断交付。

## 2:15–2:45：工程化与价值

除了功能，我补充了稳定退出码、路径脱敏、无效策略失败关闭、单元测试、CI、使用文档和响应式 HTML 报告。它的价值在于把个人经验变成可配置、可追踪的团队规则，也可以继续扩展为课程项目检查、实验室数据交付规范或 GIS 项目持续集成的一部分。

## 2:45–3:00：边界与后续

目前它只检查保存状态和元数据，不扫描要素内容，也不自动修复工程。下一步我会增加规则插件接口、更多 ArcGIS Pro 版本验证，以及项目打包前后的可移植性对比。这个项目主要体现了我把 GIS 专业问题抽象成工程工具，并通过真实案例验证的能力。
